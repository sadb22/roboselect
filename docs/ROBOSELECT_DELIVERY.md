Исходная версия: `1b19de3453010d9a0e87b24473e4278741ba5740`, получена из существующего репозитория `sadb22/roboscope`. Изменения находятся в локальной рабочей копии. Сервер Render и удалённая БД этой работой не изменялись.

Изучены оба PDF ТЗ, изображение страницы 01/05 брендбука, архив парсера (README, контракт 88 полей, сценарии, источники, нормализация, цены, HTML-обработчики, CLI, валидатор и тесты), HANDOFF и пользовательская таблица. `REMAINING_WORK.md` отсутствует. Приложен один лист брендбука: точные шрифтовые файлы и оригинальный вектор логотипа не предоставлены. Цвета и геометрия знака воспроизведены по изображению, это не исходный фирменный SVG.

## Изменённые части

- `workflow/provenance_models.py`, `models.py`, миграции `0002–0004`: нормализованные таблицы и перенос ссылок на существующий каталог.
- `workflow/provenance.py`: проверка SHA-256, неизменяемые снимки и наблюдения, выбор и отклонение, история, конфликты, неизвестные метки.
- `workflow/catalog.py`: импорт 3.3.0, повторный импорт, связь с существующими версиями; публикация импортированных ТТХ использует явно выбранные значения.
- `workflow/web_import.py`: ограниченная HTML-загрузка, проверка публичных IP, TLS с исходным именем хоста, повторная проверка перенаправлений, лимиты размера/времени, сохранение ошибки.
- `workflow/review_views.py`, `urls.py`, `templates/workflow/review_*`: рабочее место администратора.
- `config/urls.py`, `core/views.py`, обе формы входа и JavaScript: регистрация отсутствует, роль проверяется сервером, клиент не получает права по параметру URL.
- `static/roboselect.css`, `roboselect-mark.svg`, шаблоны главной страницы и основы: новая тема, два входа, постоянный дисклеймер, адаптивные таблицы.
- `vendor/robot_parser/`: приложенная версия 3.3.0; единственная дополнительная правка парсера — POSIX-пути снимков для переносимости экспорта.
- `workflow/test_provenance.py`, `test_migration.py`, `core/tests.py`: новые проверки, изменение теста регистрации на запрет, сохранение проверки привязки гостевой симуляции при входе.

## Отображение схемы

| Таблица | Реализация и правило |
|---|---|
| `robot` | Одна внутренняя идентичность; стабильный ключ парсера либо ссылка на прежнюю модель. Автоматического слияния разных поставщиков/комплектаций нет |
| `warehouse_spec`, `cleaning_spec` | Необязательные 1:1, создаются при выборе характеристики соответствующей области. Словарь типизированных значений JSON использует контракт `fields.json`; выбор всей группы колонок не выдумывался |
| `scenario`, `robot_scenario` | Справочник и уникальная связь; исходная классификация остаётся непроверенной, отсутствие связи не означает несовместимость |
| `robot_offer` | Предложение отдельно, с валютой, диапазоном, минимальной партией, тарифным периодом и полными условиями; суммы остаются Decimal-строками исходного контракта |
| `source` | Постоянный ключ, URL/имя файла, сайт, тип, результат обработки |
| `source_snapshot` | Исходные байты в БД, путь/имя экспорта, SHA-256, даты получения и обработки, версия обработчика. Байты не зависят от временной папки сервера |
| `field_observation` | Модель, поле, нормализация, исходная фраза, условия/позиция, снимок, статусы извлечения и проверки |
| `field_selection` | История решений с пользователем и временем; частичный уникальный индекс допускает только одно текущее выбранное наблюдение на поле модели |
| `review_issue` | Исходная причина и доказательства, состояние, отдельные поля результата ручной проверки |

`EquipmentRevision` остаётся снимком опубликованной карточки для расчётов. Выбор значения в нормализованной БД и публикация версии — два явных действия. Импорт не меняет опубликованную версию. При публикации импортированной версии пять поддерживаемых расчётных полей (`payload`, `width`, `length`, `min_aisle_width`, `runtime`) переносятся из выбранных скалярных значений без квалификаторов. Диапазоны и значения «до/от/при условии» сохраняются целиком, но не превращаются автоматически в рабочую характеристику. Остальные выбранные поля сохраняются в опубликованной версии как доказанные сведения; расчётная модель не получает новых неописанных правил.

Прежние `Product`, `Equipment`, `EquipmentRevision`, цены, JSON-доказательства, проекты и результаты не удаляются. Миграция создаёт связанные `robot` и сохраняет прежний указатель публикации. Старые JSON-доказательства доступны по ссылке «Открыть исходную версию»; их исторические утверждения не объявляются автоматически подтверждёнными выборами в новой схеме. Для нормализации прежнего пакета выполняется повторный импорт сохранённого экспорта.

## Локальный запуск (PowerShell)

Из каталога `roboscope`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py seed_data
.\.venv\Scripts\python.exe manage.py initialize_workflow
.\.venv\Scripts\python.exe manage.py collectstatic --noinput
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8765
```

Адрес: `http://127.0.0.1:8765/`. Клиентский аккаунт создаётся администратором в Django Admin `/admin/auth/user/add/` без `is_staff`/`is_superuser`, либо существующим `seed_data` через переменные `DEMO_USERNAME`/`DEMO_PASSWORD`. Регистрация посетителей не открывается. Для производственного окружения применяйте существующие Docker/Render-инструкции, а не `runserver`.

```powershell
# Встроенные источники → черновики; ADMIN замените именем существующего администратора
.\.venv\Scripts\python.exe manage.py import_robot_parser --user ADMIN
# Доверенный готовый экспорт
.\.venv\Scripts\python.exe manage.py import_robot_parser --user ADMIN --folder PATH_TO_EXPORT
# Отдельный CLI парсера
.\.venv\Scripts\python.exe vendor/robot_parser/add_source.py https://example.org/model --browser never
.\.venv\Scripts\python.exe vendor/robot_parser/parser.py --output tmp/parser-export
.\.venv\Scripts\python.exe vendor/robot_parser/validate_export.py tmp/parser-export
# Проверки
.\.venv\Scripts\python.exe manage.py test core workflow --noinput
.\.venv\Scripts\python.exe -m unittest discover -s vendor/robot_parser/tests -v
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

CLI `add_source.py` изменяет локальный реестр источников. Для серверных запросов используйте защищённую форму `/workspace/sources/`; она запускает изолированную копию проверенного парсера. Загружаемый ZIP — только экспорт с JSONL/снимками, а не архив исходного кода парсера.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DEBUG` | `1` локально, `0` на сервере |
| `SECRET_KEY` | Секрет Django; обязателен при `DEBUG=0` |
| `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` | Разрешённые хосты и HTTPS origins |
| `DATABASE_URL` | PostgreSQL; при отсутствии используется локальная SQLite |
| `RENDER_EXTERNAL_HOSTNAME` | Заполняется Render, добавляет хост и origin |
| `SITE_DOMAIN`, `DB_PASSWORD` | Существующая конфигурация Docker/Caddy/PostgreSQL |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Необязательное создание первого администратора командой `seed_data` |
| `DEMO_USERNAME`, `DEMO_PASSWORD` | Необязательное создание клиентского демоаккаунта той же командой |

Новых секретов для доработки не требуется. Обычный запуск `manage.py` сам не читает `.env`: переменные передаются процессу либо средствами Docker/Render. Реальные значения в отчёт не включены. Проверка браузера создаёт локального сотрудника `local-review` с **непригодным для входа паролем** и краткоживущую тестовую сессию, которая удаляется после проверки.

## Противоречия и ограничения

1. ТЗ описывает зарегистрированного пользователя, ваш текущий запрос закрывает регистрацию. Существующие аккаунты, проекты и права сохраняются; новые выдаются администратором.
2. HANDOFF упоминает отсутствующий `REMAINING_WORK.md`. Работа опирается на код релиза и реально предоставленные материалы; неизвестные поручения из отсутствующего файла не восстановлены по догадке.
3. Дополнения требуют использовать `catalog_export_v5`, архив содержит v4. Каталог не переименован и не выдан за v5. Цены нельзя считать актуальными рыночными предложениями без проверки.
4. Дополнения рекомендуют амортизацию, принятая финансовая модель считает денежный поток. CAPEX учитывается один раз; неденежная амортизация не вычитается повторно. Бухгалтерская прибыль не заявляется. Кредит/лизинг — опциональная, не реализованная ветка.
5. Полный путь расчёта реализован для склада. Аэропорт/медицина доступны в прежнем модуле на уровне выбора, параметров и обзорного подбора. Это допустимая граница MVP из раздела 2 ТЗ, но не полная экономика трёх типов объектов.
6. Веб-форма обрабатывает доступный HTML. JavaScript-страницы, PDF/DOCX, сканы, произвольные XLSX не обещаны: отображается ошибка/причина. Отдельный CLI парсера поддерживает опциональный браузер согласно своему README. Регулярный сбор и фоновая очередь веб-источников не добавлены.
7. Для HTML без производителя/назначения наблюдения сохраняются, но создание `EquipmentRevision` останавливается с ошибкой строки импорта. Недостающие сведения можно дополнить через кнопку создания связанной карточки. Слияние дублей разных реестров, отдельное подтверждение сценариев и сложных коммерческих условий требуют дальнейшего развития интерфейса. Назначение не угадывается из названия.
8. Старые доказательства не массово объявляются новыми подтверждёнными данными. В нормализованные таблицы наблюдений они попадают через повторный импорт; исходный JSON и публикация остаются сохранёнными.
9. Перенос на PostgreSQL предусмотрен ORM/миграциями, но в этой среде проверена SQLite. Нагрузочный прогон 50 пользователей, восстановление серверной БД и запуск Docker/HTTPS на целевом хостинге не выполнены. Производительность live-сайтов не гарантируется.
10. Существующие `output/*.pdf`, `*.pptx` относятся к предыдущему релизу и не обновлены под RoboSelect. Их нельзя выдавать за финальный пакет этого изменения. Новые сведения переданы в Markdown; отдельное обновление презентации и документов остаётся перед конкурсной сдачей.
11. Подбор ограничен текущим каталогом и конечным перебором. Инженерные траектории, столкновения, реальные интеграции WMS/ERP, государственные реестры, платежи и юридическое подписание не реализованы. Учебные заказы остаются явно демонстрационными.
